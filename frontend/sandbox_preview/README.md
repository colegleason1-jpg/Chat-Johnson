# sandbox_preview (Run-mode component)

A hand-written Streamlit declared component, no build step: `declare_component("chat_johnson_sandbox_preview", path=<this dir>)`.
`main.js` builds the nested document with the exact `orchestrator.sandbox_preview.build_document` rule: the Python-owned insert
(`sandbox_insert`) goes in a wrapper `<!doctype html><html><head>…</head>` PREPENDED on the page's first line, no newline, so the shim
runs before any page script, the parser merges the page's own head children into that head, and browser line numbers are page line numbers.
The result is hosted in a nested `<iframe sandbox="allow-scripts" srcdoc>` (opaque origin: no cookies, storage or parent access); nothing from it is ever relayed to the parent.

One report per run: the shim's talk-back is aggregated and posted ONCE via `streamlit:setComponentValue` at settle time (ready, navigated,
blank or the 8 s timeout) and never again for that run, because Streamlit treats every value as a rerun request and would abort a running
fix turn. Later events (a click that throws) only update the status bar text. Status precedence: error (an uncaught error or a
`console.error`) > navigated > blocked (a refused `script-src`/`style-src` dependency) > blank > ready > timeout.

Two frames: component document (this directory, `script-src 'self'`) -> nested opaque-origin frame (the page plus `CHILD_CSP`). A srcdoc
frame inherits its host document's CSP on top of its own, so the `<meta>` policy in `index.html` must be `COMPONENT_CSP` verbatim: it mirrors
the child's policy (no network, no external scripts) and its `frame-src 'none'` is what refuses the nested frame navigating itself to http(s).

`vendor/three.datauri.js` (Three.js r160 core, MIT, `vendor/THREE_LICENSE`) is generated by `scripts/build_three_datauri.py`; it is loaded
lazily, only for pages that import `'three'`, and reaches the page through an import map pointing at the data: URL.
